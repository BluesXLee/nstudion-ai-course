# 🦀 從 Go 到 Rust：深度技術轉型指南 (Deep Dive)

這是一份為資深 Go 開發者量身打造的技術指南。它不討論語法細節，而是討論**內存模型、併發哲學與類型系統**的根本差異。

---

## 1. 內存模型：從「管理」到「所有權」

在 Go 中，你習慣了「分配即使用」的模式。在 Rust 中，你必須理解「生命週期」與「所有權」。

### 1.1 Go 的思維：GC 與 指針
在 Go 中，當你寫 `p := &user` 時，你是在分配一個指針。你不需要擔心 `p` 是否會指向一個無效的地址，因為 GC 會確保只要還有指針存在，對象就不會被回收。

### 1.2 Rust 的思維：Ownership (所有權)
Rust 沒有 GC，它使用 **Ownership** 規則來決定內存何時釋放：
1. **每個值都有一個變數，稱為它的「所有者」(Owner)**。
2. **同一時間只能有一個所有者**。
3. **當所有者離開作用域時，值會被自動銷毀**。

#### 關鍵概念：Move vs Copy
* **Move (移動)**：當你將一個擁有堆內存（如 `String`）的變數賦值給另一個變數時，所有權會「轉移」。原變數變為無效。
* **Copy (拷貝)**：對於存放在棧（Stack）上的簡單類型（如 `i32`），Rust 會自動進行拷貝。

**Go vs Rust 範例：**
```rust
// Go: 隨意賦值
// u2 := u1 (這只是指針拷貝或結構體拷貝，GC 會處理)

// Rust: 所有權轉移
let s1 = String::from("hello");
let s2 = slet s1; 

// println!("{}", s1); // ❌ 編譯錯誤！s1 的所有權已經移交給 s2，s1 已失效。
```

### 1.3 借用規則 (The Borrowing Rules)
為了避免在移動所有權時感到不便，Rust 引入了「借用」：
* **不可變借用 (`&T`)**：你可以同時擁有無數個讀取者。
* **可變借用 (`&mut T`)**：你只能擁有**一個**寫入者，且此時不能有任何讀取者。

**這解決了 Go 中常見的 Data Race 問題：** 在 Go 中，你可能在一個 Goroutine 讀取，另一個 Goroutine 寫入。在 Rust 中，這在編譯階段就會被攔截。

## 2. 錯誤處理：從「檢查」到「類型約束」

### 2.1 Go 的哲學：顯式檢查
Go 的 `if err != nil` 是為了讓錯誤處理變得「可見」。它很直觀，但它不強制你處理錯誤，你可能會漏掉。

### 2.2 Rust 的哲學：類型安全 (Type-Safe Error Handling)
Rust 使用 `Option<T>` 和 `Result<T, E>`。這不是函數返回，而是**包裝了值的類型**。

* **`Option<T>`**：代表一個值「可能存在，也可能不存在」。
* **`Result<T, E>`**：代表一個操作「可能成功，也叫失敗」。

**對比：**
在 Go 中，你可能返回 `(User, error)`。如果開發者忽略了 `error` 直接使用 `User`，程式會崩潰。
在 Rust 中，你必須先「解開」`Result` 才能拿到 `User`。

```rust
// Rust 的模式匹配 (Pattern Matching)
match result {
    Ok(user) => println!("User: {}", user.name),
    Err(e) => println!("Error: {}", e),
}
```

## 3. 併發模型：從「輕量級線程」到「無畏併發」

### 3.1 Go: CSP (Communicating Sequential Processes)
Go 的核心是 Goroutines。它們非常輕量，透過 Channel 通訊。雖然很強大，但 Go 程式碼中依然可能發生 Data Race（例如多個 Goroutine 訪問同一個 Map）。

### 3.2 Rust: Fearless Concurrency
Rust 的併發不是靠運行時（Runtime）支撐，而是靠**類型系統**。
* **`Send` Trait**：如果一個類型實現了 `Send`，它就可以安全地從一個線程轉移到另一個線程。
* **`Sync` Trait**：如果一個類型實現了 `Sync`，它就可以安全地在多個線程間透過引用共享。

**核心差異：**
在 Go 中，併發是「運行時」的挑戰。
在 Rust 中，併發是「編譯時」的挑戰。如果你的代碼存在潛在的 Data Race，Rust 編譯器會拒絕編譯。

---

## 4. 抽象與類型：從「隱式」到「顯式」

### 4.1 Go: 隱式接口 (Implicit Interfaces)
在 Go 中，只要你的結構體實現了某個方法，它就自動實現了接口。這非常靈活，但也可能導致依賴關係變得模糊。

### 4.2 Rust: Trait (顯式實現)
Rust 的 `Trait` 類似於接口，但它更強大。你必須顯式地為類型實現 Trait。
* **Zero-cost Abstractions**：Rust 的 Trait 實現通常在編譯時進行「單態化 (Monomorphization)」，這意味著泛型代碼在運行時與手寫的具體代碼性能完全一致。
